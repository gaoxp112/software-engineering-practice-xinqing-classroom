# 需求规格说明

## 1. 项目背景

课件第 5 页将 Emoji project 定义为课堂情绪检查系统：学生反馈有助于理解课程内容、课程有效性和学生对材料的理解，教师可据此及时调整教学。第 6 页要求客户端、后端和管理端协作，并建议采用修改版 MVC。

## 2. 角色与功能

| 角色 | 功能 |
| --- | --- |
| 学生 | 注册、登录、改密、加入开放课堂、发送 emoji、匿名提交、查看历史 |
| 教师 | 注册、登录、改密、创建/结束课堂、加入课堂提交 emoji、查看本人历史、看课堂统计、导出课堂 CSV |
| 管理员 | 登录、查看用户、查看全局 emoji 数据、统计情绪分布、启用/停用用户、导出 CSV |

课件第 7-8 页明确了学生/教师端和管理端的功能；第 6 页明确管理端需要查看用户信息、安排特定时间的用户列表并导出文件，因此系统加入了 `session_participants` 课堂参与关系表。

## 3. 非功能需求

- 本机离线运行，课堂数据存储在 SQLite 中。
- 数据持久化到 SQLite，密码不得明文保存。
- 桌面端和移动端均可操作，关键文本不溢出。
- 关键写操作具备 CSRF 防护、角色检查和资源归属检查。
- CSV 导出带 UTF-8 BOM，便于 Excel 打开中文。

## 4. 范围声明

课件第 16 页将表情识别列为 AI 增强方向。教师可在开放课堂主动开启本机摄像头，查看实时人脸框和六类情绪。系统将达到置信度阈值的采样作为匿名反馈纳入当前课堂统计。
