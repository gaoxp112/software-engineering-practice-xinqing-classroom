# 表情符号课堂情绪检查器系统结题报告

课程：软件工程实践  
系统名称：心晴课堂  
报告日期：2026 年 11 月 3 日

## 摘要

本实验面向课堂反馈不及时、学生感受难以持续记录的问题，设计并实现了“心晴课堂”表情符号课堂情绪检查器。系统采用 Flask、SQLite、Jinja2 和原生 CSS/JavaScript，提供学生、教师、管理员三类角色的浏览器端功能。学生可以加入课堂、选择六类情绪、补充说明、匿名提交并查询个人历史；教师可以创建与结束课堂、查看课堂反馈和统计；管理员可以维护用户与课堂名单、按条件查看数据并导出 CSV。系统同时提供 REST API、独立 AI 服务认证、AI 结果置信度过滤与匿名入库能力。

截至 2026 年 11 月 3 日，演示数据库包含 17 个用户、13 个课堂、223 条情绪记录和 155 条课堂参与关系，具备多教师、多课堂的演示场景。自动化测试共 24 项，全部通过；桌面端和移动端视觉验收覆盖核心学生、教师及管理员流程。新增的视频 AI 工作器可抽取 MP4 视频帧、调用视觉模型判断是否检测到人脸并分类表情、按 0.65 置信度阈值过滤，再经独立服务令牌写入指定课堂。自动化集成测试使用本地模拟视觉 API 和隔离 SQLite 验证整条链路，另使用配置的视觉 API 在数据库副本中完成了实际写入和管理端查看。原始视频及临时帧不会进入课堂数据库；抽取帧会发送给第三方 API，因此演示优先使用本项目提供的虚构成年人物视频。

关键词：课堂反馈；情绪检查；修改版 MVC；角色权限；REST API；响应式界面

## 1 项目背景与目标

课堂中，教师通常通过提问、观察和课后反馈判断学生的理解程度。这些方式能够提供信息，但不便连续保留，也容易遗漏不主动表达的学生。本系统让学生用简短的情绪选择表达当前感受，并把反馈关联到具体课堂和时间，帮助教师发现需要补充解释、调整节奏或安排休息的时段。

系统的目标不是根据情绪给学生贴标签，而是建立一个操作简短、记录可追溯、角色边界清楚的教学反馈工具。项目围绕学生提交、教师观察、管理员管理与导出的完整流程组织功能，并通过需求、设计、测试和部署材料记录软件工程实践过程。

需求依据包括《软件工程00 简介》课件与《表情符号课堂情绪检查器系统》实验指导书。课件强调三类角色、课堂情绪记录、历史查询、统计与导出；新指导书进一步补充了统一 REST API、课堂用户安排、多维统计、AI 结果入库以及视频推理流程。本报告以当前代码与验收证据说明实际完成范围。

## 3 系统设计与实现

### 3.1 总体架构

浏览器向 Flask 应用发送请求。HTML 控制器通过 Service 执行业务操作，再渲染 Jinja2 页面。REST 控制器复用 Service，并以统一 JSON 格式返回结果。CSS 完成桌面与移动布局适配，JavaScript 更新图表和课堂页面。

系统请求依次经过 Flask Controller、Service、Repository 和 SQLite。视频工作器用 FFmpeg 抽帧，在本机完成表情分类，将映射结果通过独立服务令牌提交给课堂 API。实时摄像头工作器复用同一模型和六类映射。

`auth.py`、`main.py`、`teacher.py`、`admin.py` 和 `api.py` 接收请求并组织响应。`services.py` 统一处理认证、课堂归属、名单校验、情绪入库、统计和导出。`repository.py` 负责参数化 SQL，`db.py` 负责数据库初始化和迁移。

### 3.2 角色权限与安全

学生只能访问自己的历史记录；教师只能管理自己创建的课堂；管理员可以查看全局用户、课堂与情绪数据。权限检查在后端执行，不能仅通过隐藏页面按钮代替。AI 入库接口使用独立服务令牌，与学生或教师登录会话分开。

密码通过 Werkzeug 生成加盐哈希，数据库不保存明文密码。页面写操作使用 POST 和 CSRF 校验，SQL 使用参数绑定，情绪类型使用枚举约束。CSV 导出添加 UTF-8 BOM，便于 Excel 显示中文，并处理可能触发电子表格公式的字段。对于无效日期、倒置时间范围、无效参与者和越权访问，系统拒绝请求或返回明确错误。

### 3.3 API 设计

API 以 `/api` 为统一前缀，主要覆盖认证、当前用户、开放课堂、情绪提交、历史、统计、课堂排班、实时汇总、导出和 AI 入库。响应采用 `ok` 与 `data` 或 `error` 的统一结构，便于调用方判断结果。机器可读接口契约位于 `/api/openapi.json`。

代表接口包括 `POST /api/emoji`、`GET /api/emoji/history`、`GET /api/admin/dashboard/realtime`、`GET /api/admin/statistics` 与 `POST /api/ai/emoji-results`。多维统计可按课程、班级和时间段筛选。AI 接口会返回接收与拒绝结果。工作器对外部视觉请求和后端写入均不自动重试；发生网络错误时会报告失败，由操作者决定是否重新运行，以避免不确定响应造成重复计费或重复写入。

## 4 数据库设计

系统使用关系型 SQLite 数据库，数据文件位于 `instance/emotion_checker.sqlite3`。主要实体如下。

| 实体与表 | 核心数据 | 关系与用途 |
| --- | --- | --- |
| 用户 `users` | 用户名、显示名、密码哈希、角色、邮箱、状态、创建时间 | 教师创建课堂，用户加入课堂并提交反馈 |
| 课程 `courses` | 课程名、教师 ID、创建时间 | 教师 ID 关联用户，一个课程可对应多次课堂 |
| 课堂 `class_sessions` | 标题、课程 ID、班级、教室、代码、开始与结束时间、状态 | 通过 `course_id` 外键关联课程，一个课堂可对应多条反馈 |
| 参与关系 `session_participants` | 课堂 ID、用户 ID、加入或安排时间 | 复合主键避免重复安排，表达课堂与用户的多对多关系 |
| 情绪记录 `checkins` | 课堂、可空用户、情绪、说明、匿名标记、来源、置信度、设备、时间 | 保存人工反馈和规范化 AI 结果 |
| 审计日志 `audit_logs` | 用户、操作、说明、时间 | API 注册、登录、改密、提交、排班、AI 入库与导出写入日志；HTML 路径的覆盖尚待统一 |

人工反馈支持同一用户在同一课堂多次提交，用于保存变化过程，因此“反馈条数”与“参与人数”是两种不同指标。匿名人工反馈仍保留用户关联以供本人查询，但教师页面与教师导出隐藏其身份；匿名 AI 记录可以没有用户 ID。

数据库为情绪记录的课堂时间查询和用户时间查询建立索引。启动时执行幂等初始化与迁移，补充邮箱、班级、教室、AI 元数据及相关表。旧版本非空用户限制的迁移会复制既有记录，允许匿名 AI 数据。演示数据库验收快照为：17 个用户、13 个课堂、223 条情绪记录、155 条参与关系。

## 5 核心功能与使用画面

### 5.1 学生课堂反馈

学生登录后进入进行中的课堂列表，也可以输入课堂代码加入。课堂卡片集中展示课程、课堂主题、教师、代码和个人提交次数，点击“记录感受”即可进入反馈页。反馈页提供开心、平静、困惑、疲惫、焦虑、分心六类选择，可填写不超过 240 字的说明，并选择匿名提交。

从操作路径看，课堂选择与反馈填写被分为两个清楚的步骤。表情与中文名称一起出现，有助于减少仅看图标造成的歧义；选中状态以底色、边框和勾选标识共同表达。补充说明可把“困惑”落实到某个知识点，比单一表情更利于教师处理。提交后，学生可以在历史中回顾自己的记录。

### 5.2 教师课堂管理与观察

教师在课堂管理页面创建课堂，填写课程、主题、班级和教室等信息。系统生成课堂代码，学生通过代码参与。教师卡片按课堂展示开放状态、参与者数量和反馈次数，支持进入看板；课程结束后可关闭课堂，避免继续提交。

教师看板聚合本课堂情绪分布、积极率、最近反馈和参与情况，并支持导出课堂 CSV。多课堂卡片让教师能够区分不同主题与班级。新增的班级与教室字段减少了仅凭标题区分课堂时的混淆，也使班级维度的统计更有明确的数据来源。

### 5.3 管理员统计与导出

管理员可以查看用户、课堂安排、情绪记录与统计概览。概览使用数字卡片展示用户数、课堂数、筛选范围内反馈数和开放课堂数；情绪数量、占比与时间趋势分别适合观察数量差异、结构和变化过程。记录页支持日期及情绪筛选，导出 CSV 便于后续分析与归档。

界面采用浅色背景、白色卡片、深绿色文字与珊瑚色主要按钮。数字与动作入口有较明显的层级，教师和管理员在查看数据时可以先获得总体信息，再进入明细。统计时必须先确认筛选范围：当前管理员桌面截图中的 156 次反馈对应 2026 年 10 月 20 日至 27 日，不能视为数据库全部 223 条记录。

### 5.4 移动端使用观感

移动端将导航折叠为菜单，课堂卡片改为单列排列，主要按钮保持明显的点击区域。360 像素宽度的验收画面能够阅读课堂主题并完成主要操作。对于数据列较多的管理员表格，系统使用表格内部横向浏览，阅读时需要滑动；这保持了列的完整性，也意味着管理操作在桌面端更高效。

本次使用观感依据真实页面与操作流程检查，未开展学生或教师的问卷调查，不能据此推断长期教学效果或用户满意度。可以确认的是：学生反馈入口清楚、表情选择状态明确、教师能区分多个课堂、管理员能获得汇总和明细两种视角。

### 5.5 AI 视频分析

系统提供独立的视频工作器和一键演示入口。工作器默认每隔约 3.3 秒抽取一帧，最长处理 60 帧；每帧经视觉 API 返回人脸是否可见、六类情绪之一和模型自报置信度。只有检测到人脸、情绪标签有效且置信度达到 0.65 的结果才会写入最近开放的课堂。教师或管理员可在情绪数据页区分 AI 来源并查看置信度。

项目准备了三段 10 秒、H.264 MP4 案例视频，画面为 AI 生成的虚构成年人物，不对应真实个人。演示时双击项目目录中的 `run_video_demo.bat`，系统自动选择最近开放的课堂并弹出视频选择框；选择素材后，脚本启动临时本地服务、调用外部视觉 API、提交情绪结果并打开管理端记录页。操作者仍需登录管理员账号核验记录。模型返回的 confidence 是模型自报分数，不是校准后的准确概率。

## 6 测试与质量验收

### 6.1 功能与接口测试

2026 年 11 月 3 日执行 `python -m unittest discover -s tests -v`，24 项测试全部通过，耗时 13.598 秒。测试覆盖健康检查、三类角色、账户管理、学生反馈、教师课堂归属、管理员筛选和排班、CSV 导出、错误输入、权限边界及 API 契约。视频工作器集成测试使用真实 MP4 文件和 FFmpeg 抽帧，以本地模拟视觉 API 产生情绪结果，再通过运行中的 Flask API 写入隔离 SQLite，确认数据库中的 AI 来源、情绪、置信度及时间字段正确。

此外，使用配置文件中的真实视觉 API 对两段生成视频进行了端到端检查。五条结果写入独立的数据库副本，并在管理端记录页验证来源、置信度与情绪；正式演示数据库保持原样，API 密钥未出现在代码、日志和报告中。此项验证证明当前凭据、模型和网络在测试时可用，不代表未来网络或服务额度始终可用。

测试从正向流程与异常边界两方面验证了系统。学生不能进入管理员功能，教师不能查看其他教师的课堂；无效参与者不会替换原有名单；关闭课堂后不能继续正常提交。测试通过说明这些已覆盖路径在当前环境下符合预期，不能替代真实公网并发或全部浏览器兼容性测试。

### 6.2 性能基准

在临时 SQLite 数据库插入 10,003 条情绪记录后，本机 Flask 测试客户端得到以下结果。

### 6.3 视觉验收与问题修正

既有严格验收检查了 1366×768 桌面与 360×800 移动视口下的 16 个核心页面状态，指导书补充验收覆盖 20 幅页面截图。最近一次验收还检查了登录、学生课堂、教师课堂列表、管理员概览与课堂安排。记录显示未发现页面级横向溢出、控件裁切或空白图表，移动表格通过内部横向浏览保持可读。

迭代中修正过匿名反馈参与人数合并、24 小时时区与分桶、日期校验、无效课堂名单编号等问题。新增班级、教室及 AI 来源/置信度列后，又核对了旧数据迁移、教师课堂卡片、管理员记录表与 API/CSV 字段。1366×768 桌面和 360×800 移动端的页面截图保存在项目 `docs` 下；另使用隔离数据库验收了管理员 AI 记录页面。

## 7 运行说明与验收演示流程

本地运行需要已安装 Python，并在项目目录中安装 `requirements.txt` 的依赖。可创建虚拟环境后运行 `python run.py`，或在依赖就绪后双击 `start.bat` 通过 Waitress 启动。浏览器访问 `http://127.0.0.1:5000`。首次运行自动初始化数据库与基础演示账户，数据库文件应在升级和交付前备份。视频演示还需要实验目录中的 `judge.env.example` 配置和可运行的 FFmpeg；本机可直接使用 QQ 浏览器附带版本。

本地演示账户分别为学生 `student`、教师 `teacher`、管理员 `admin`，密码在项目 README 中列明；这些账户仅用于实验演示。视频工作器会逐帧调用配置的视觉 API，因此每个采样帧可能产生一次计费请求。默认 10 秒案例约调用三次；单段视频最多抽取 60 帧。密钥保存在实验目录之外的本地配置文件，不能加入代码仓库或提交包。

建议现场演示时先用教师账号创建或确认一场开放课堂，再展示学生登录、提交“困惑”和知识点说明、教师查看课堂反馈、管理员查看统计和导出。最后运行 `run_video_demo.bat`，选择一段 10 秒素材并展示 AI 来源与置信度记录。演示账户见 README；一键流程默认使用最近开放的课堂，若要指定其他课堂，可运行 `python scripts\\run_video_demo.py --choose-session`。

如需复核，可执行 `python -m unittest discover -s tests -v` 和 `python tests\\benchmark.py`，并通过 `/api/openapi.json` 查看接口契约。系统源码、文档、测试和三段 AI 生成案例视频已在本地项目目录准备好；最终仍需由项目成员录制屏幕演示视频并按课程平台要求提交。

## 8 局限与后续改进

### 8.1 AI 能力与误判风险

视频 AI 流程已经实现并在隔离环境完成端到端验证，但它通过第三方视觉 API 推理，不是本地部署模型。抽取帧会发送到配置服务；请求设置 `store=false`，但该参数不等同于服务商承诺零保留，使用前仍需核对实际数据政策。工作器不会对不确定失败自动重试，以减少重复计费和重复写入；用户可在确认上一请求状态后手动重跑。

即使补齐模型，表情分类结果也不等同于个人真实情绪或心理状态。光照、遮挡、摄像头角度、表情习惯、文化差异与训练数据偏差都会导致误判。高置信度表示模型对类别的判断强度，不能直接证明判断正确。教学应用应优先参考匿名聚合趋势，并结合学生主动反馈和课堂情境，不应把结果用于心理诊断或单独评价学生。

系统不保存原始视频、抽取帧或人脸特征，后端 API 只接收情绪类别、模型置信度、时间和设备标识。视频中的人物应已知情同意；本项目提供的虚构成年人物素材可用于课堂演示。表情分类会受到光照、遮挡、姿势和文化差异影响，模型自报置信度不是正确率，结果不能用于心理诊断、考勤或学生评价。

### 8.2 架构与部署改进

业务校验、统计和导出由 Service 组织，Repository 统一执行 SQL。数据库升级按课程名称和教师匹配既有课程，并保留课堂、参与名单与反馈记录的关联。

目前的实时看板以请求获取汇总数据，尚无 WebSocket 推送。后续应根据课堂规模确定轮询或推送方案，并补充并发、断线恢复和统计一致性测试。用户体验方面，可增加筛选条件的可见提示、移动端表格字段折叠与无障碍检查，再通过真实学生和教师试用收集改进意见。

团队分工与贡献度、真实 Git 提交记录、远程仓库地址和演示视频需随最终提交包整理；报告不代填未确认的成员身份或贡献比例。

## 9 结论

本项目完成了以课堂情绪反馈为中心的系统，实现学生提交、教师观察、管理员管理与导出的闭环，并补齐视频抽帧、视觉 API 情绪分类、置信度过滤和匿名结果入库。24 项自动化测试、真实 API 隔离写入、数据迁移检查和桌面移动视觉验收为当前功能提供了可复核证据。

项目目录中的源码、运行说明、数据库初始化与迁移、需求和设计文档、接口契约、测试报告、截图及案例素材均已准备完成。现场展示仍依赖本地 Python 环境、可用的视觉 API 配置和网络；最终需录制演示视频并完成课程平台提交。进一步分层、统一 HTML 审计链和公网部署属于可以继续迭代的工程改进，不影响当前本地实验流程。
